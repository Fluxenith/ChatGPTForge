# Shared global memories

Forge provides an explicitly enrolled shared store in its state SQLite database. It is separate from private `.serena/memories` files and from external Serena's native global directory. Private memories are never automatically published. Use the six `global_memory_*` tools; ordinary Serena read/write routes do not read this store.

1. Create or resume an active leased task for each project to share. Call `global_memory_preview` with `action: "enroll"` and participant task IDs. Enrollment is explicit and can add projects to an existing group.
2. Call `global_memory_apply` with the preview's global fingerprint, every participant's project fingerprint and write lease, and a new operation ID. Keep these exact arguments for replay.
3. Preview/apply `action: "write", name: "global/topic", content: "..."`. Every enrolled project reads the same current value using `global_memory_read`. Updating content updates the shared source immediately; references resolve to that shared source, rather than copying content into private memories.
4. Preview/apply `action: "rename", name: "global/topic", to: "global/new-topic"`. Inspect changed paths first. Exact `mem:global/topic` links in all enrolled project memories and other shared memories change together. Similar names, longer topic paths and unrelated text remain unchanged.
5. Inspect `global_memory_operation` after a timeout. Replay identical IDs/arguments only to retrieve receipts. For pending intent, call `global_memory_recover` with every original participant lease and explicit `finish` or `rollback`. Conflicting external edits are refused; inspect them before retrying.
6. To undo a completed change, call `global_memory_rollback` with its `change_id`, a fresh `operation_id`, all current leases/project fingerprints and current global fingerprint. Undo subsequent shared changes first. Rollback also restores propagated links; undoing creation removes that shared memory, and undoing enrollment restores membership/markers.

Every shared write requires active tasks and leases for **all enrolled projects**, even a content update. Preview returns the required participant fingerprints; missing projects are refused. Maximum 8 projects, 128 shared memories, 64 changed files per transaction, 64 KiB per memory and 2 MiB total state. No implicit enroll-all, native Serena import, group partitioning or general-purpose unenrollment is provided in this version.

Each participant has `.forge-shared-memory.json`, whose shared-state fingerprint is included in normal task snapshots and verification. Do not edit this marker manually. Shared changes invalidate prior verification through project fingerprint changes. Complete tasks only after final verification. Normal writes, handoff and cancellation are fenced while a shared transaction is pending.

The coordinator commits intent before file writes. Each replacement is atomic; the whole multi-project filesystem change is **not** atomic. Pending state prevents shared reads and further task writes until explicit recovery. Recovery validates the original root identities and before/after file hashes and refuses unrelated concurrent project changes. Completed rollback preserves unrelated edits and refuses externally changed targets. Receipts contain metadata; backups remain in the local state database. Historical completed receipts do not assert that their state is still current.

Serena read-only and ignored-memory policies remain enforced for planning new writes and renames. An ignored local memory prevents a complete rename scan and causes refusal. Recovery and rollback restore the previously recorded intent rather than replanning under changed policies; recover before changing project policy. Symlinks, special files, overlapping roots and case-insensitive name collisions are refused.
